## User Story

**As** the owner,
**I want** Zyggy on Central to read my Digiverse mailbox and drives, leave a morning brief with numbered suggested actions, and — when I ask in my remote session ("send 1", "do 1 and 3", "save this as a file in Projects/Calizr") — to send the e-mail, create the new document in my OneDrive, or file or soft-delete a mail, each only after a permission prompt on my phone or claude.ai that shows me exactly what will be sent or created and that I answer myself,
**So that** Zyggy can act for me with one tap per action, nothing ever leaves my mailbox or lands in my OneDrive without that tap, and no timer run, backfill or injected mail can act on its own.

**As** Central,
**I want** the three action tools to exist only in the interactive session, behind an ask rule the model cannot satisfy, a hook that refuses anything outside policy before the prompt appears (attachments, hidden recipients, HTML bodies, overwrites, foreign drives), and a log of every executed action that the owner can reconcile with the Exchange audit log,
**So that** every executed action maps to one prompt the owner answered, and the identity's tenant-side scope bounds what a leaked key could do.

**As** the owner maintaining the template,
**I want** the rules, hooks, wrapper, skills and tests generic in `zyggy-core` and every Digiverse fact in my instance,
**So that** a template change reaches Central with a fast-forward pull.

**Design (decided, OQ-D8-1 (C)): the server runs in plain HTTP mode on loopback and Claude Code fetches a fresh token per connection through `headersHelper`.** Nothing sits between Claude Code and the server any more; the token is minted where Claude Code needs it and never reaches the server's environment.

```
claude (session / -p) ──HTTP, Authorization: Bearer <fresh>──▶ 127.0.0.1:<port>/mcp  ms-365-mcp-server --org-mode --http
        │ on connect, reconnect, and on a 401 from a tool call                    (zyggy-m365-mcp.service, env -i, no token)
        └─ runs mcp-auth-header.sh ── graph.sh token (only reader of the key) ──▶ Entra (certificate client assertion)
```

Refresh sequence: the token's `exp` passes → the next tool call reaches the server's middleware, which answers **HTTP 401 before any tool runs** → Claude Code re-runs the helper (one `graph.sh token`), reconnects (the server is stateless — no session to rebuild) and retries the call once → answered. There is no refresh timer and no threshold: the server's own `exp` check is stricter than Graph's clock-skew allowance, so the expired token is caught at the door, not inside a tool (residual: a token expiring during the milliseconds of one Graph call → that one call returns a tool error; the next call refreshes).

## Behaviors & Conventions

- **Consent = the prompt.** Each call to an action tool shows a Claude Code permission prompt on whatever device the owner uses (terminal, claude.ai, phone — Remote Control keeps it open until answered). Allow → executed once; Deny → not executed, Claude stops. The ask rule cannot be bypassed by an allow (including one written by "don't ask again"), by auto mode, by the classifier or by a hook. Override: `actions.enabled` may narrow; the template's ask list is not instance-editable (an instance may only add, never remove, settings rules — 27 rule).
- **Session-only.** Every unattended run (`brief.sh`, backfills, any `claude -p`) denies the action tools explicitly and runs with `--permission-prompts none`; no `PermissionRequest` hook exists. Override: none.
- **Policy before consent.** `m365-guard.sh` refuses calls outside policy before a prompt appears; on its own failure it blocks (exit 2); on timeout the ask rule still prompts (policy lost, consent kept). Override: `actions.*` limits in the instance.
- **What the model can and cannot do (honest statement).** Can: read the mailbox and granted drives; create Drafts; **request** a send (any recipient, plain text, no attachment, no Bcc), a new OneDrive file (text formats, new name, OneDrive only) or a move / soft delete — each executed only if the owner answers Allow. Cannot: act in any run without the owner; overwrite, rename, delete or share files; hard-delete mail; send attachments or Bcc; read the key through recognised readers. The owner's Allow is the only gate between a requested send and a sent mail.
- **Recipients are not bounded by policy** (owner decision D7: Zyggy may e-mail anyone the owner allows). The bounds are: the prompt shows them (fact (1)); the rule requires the full message in the reply first; Bcc and attachments refused; ≤ 10 recipients; the audit reconciliation after the fact.
- **Audit after the fact.** `actions.jsonl` (per call), the Exchange/SharePoint unified audit log (per app id) and the monthly reconciliation (runbook) — any `Send`/`Move`/`FileUploaded` by the app id without a log row means the key was used outside Claude Code → revoke.
- **Token refresh without the owner (D8).** The `m365` credential is re-minted by Claude Code's `headersHelper` on every (re)connection and on the first tool call after the token expired; the owner never reconnects. Overrides: `ZYGGY_M365_PORT` (loopback port, default 47365), `ZY_M365_HELPER_SECONDS` (helper budget, default 8, must stay below Claude Code's 10 s). Section "D8".
- All other behaviors unchanged (brief, Drafts audit, backfills, caps, facts, parse-and-discard, five attended runs, interactive reads, data protection). ~~hourly reconnect~~ — superseded by D8.
