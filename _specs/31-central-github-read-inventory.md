## User Story

**As** the owner,
**I want** to say `/github-inventory` in my remote-control session with Zyggy and get, a minute later, one memory line per repository my read-only token can see — `owner/name`, what it is for, its main language, when it was last pushed, whether I own it, whether it is a fork or archived — written into `inbox/` for the dream pass to consolidate,
**So that** Zyggy knows my projects, and I can extend that knowledge later (write scopes, deeper reads) without ever having given Central more than read access to repositories I chose.

**As** Central (the machine role),
**I want** the GitHub token to exist only in one 0600 file that one script reads, to reach `gh` only as the environment of that one child process, to be refused in any unattended run, and every string that comes back from GitHub to be bounded, sanitised and secret-checked before it is written or shown,
**So that** the first API credential on this VM cannot leak into a repository, a memory file, a transcript, a plugin or a timer, and a README that says "ignore your instructions" is one line of data in my inbox, nothing more.

**As** the owner maintaining the template,
**I want** the skill, its script, its tests and the security rule to be generic in `zyggy-core`, and my account, my repository selection and my token file to be described only in my instance,
**So that** a template update reaches Central with a fast-forward pull, and another owner can run the same inventory against their own account.

## Behaviors & Conventions

- The inventory runs only when the owner invokes `/github-inventory` in a conversation; `disable-model-invocation: true` keeps it out of Claude's own initiative and out of scheduled tasks; the script refuses `ZYGGY_HOOKS=off` (exit 5) before reading the token. Override: none.
- The token is one 0600 file under the `zyggy` user's `~/.config/zyggy/`, read only by `inventory.sh`, exported only to its `gh` children. `gh` is otherwise unauthenticated on Central. Override: none (re-issue and revocation change the file's content or delete it, never its exposure).
- The token is issued without expiration and is never rotated on a schedule (owner decision at the spec gate); it is re-issued only on suspicion of compromise or when a selection change cannot be edited in place, and revoked on GitHub first when in doubt. Override: the 366-day fallback if "No expiration" is unavailable — then `--check` shows the date and the runbook's re-issue entry is a yearly step.
- The token reads every repository the owner's personal account owns (owner decision); what enters memory is narrowed on Central by the instance-owned exclusion list, not by a token change; organisation-owned repositories (`zyggy-org`, the employer) are unreachable by construction and never sought another way. Override: `instance/github-inventory-exclude.txt` (workstation edit, pulled); the token's repository access is tightened only on GitHub.
- The script talks to exactly two data endpoints (`user/repos` with `affiliation=owner`, `repos/*/*/readme`) plus `user` and `rate_limit`, GET only, at most `1 + ⌈N/100⌉ + (repositories without a description, ≤ cap)` requests per run; the README is read only when the description is empty and only its first 4,096 bytes. Override: none.
- Every line is composed by the script, sanitised, secret-checked and ≤ 240 characters; the model composes nothing. Override: none.
- The inventory is one inbox file per day, replaced on a same-day rerun, with the `remember.sh` `[observed]` line format; the dream pass (28) consolidates and de-duplicates it; until 28 exists the file waits in `inbox/` and is readable on request. Committing `memory/` follows the 27 rule (on the owner's request only). Override: none.
- The cap (200) keeps the most recently pushed repositories and says so in a marker line; a larger account is a template decision (raise the default) or a hand run with `--max`. Override: `--max` per invocation, ≤ 500.
- A run that fails against GitHub writes nothing (exit 6); a run refused as unattended or by configuration writes nothing (exit 5/3); the owner sees one stderr line and a runbook entry name. Override: none.
- Nothing on GitHub is written: the token cannot, the rule forbids it, the stub in CI refuses any non-GET call. Override: none until the write-scope deliverable after 18–20.
- The template names no account, selection or machine path; the instance's `instance.md` does (prose), the token's selection lives on GitHub and 0002. Override: none (AC-30 of spec 27 enforces it).
- Cloning is not part of this skill: a public repository the owner names can be cloned as ordinary Bash use into a scratch directory (its content is data); a private repository is not cloned from Central in 31. Override: none.
- Cost: one attended run's model cost is recorded once in 0002 (Max subscription, informational); the request count stays far below the 5,000/h limit. Override: none.

## Failure modes

| Situation | Observable outcome | Runbook entry (`central-claude-config.md` → Troubleshooting) |
|-----------|--------------------|---------------------------------------------------------------|
| Token file missing, empty, mode ≠ 0600, wrong owner, or `ZYGGY_GITHUB_TOKEN_FILE` misused | Exit 3, one stderr line naming the path and the condition; nothing written; `gh` never called; Claude points to the runbook | "GitHub inventory: configuration error": re-create the file per 11c (`umask 077`), `chmod 600`, `chown zyggy`, never on the VM as root's home |
| `ZYGGY_*` missing / memory dir missing | Exit 3 as in 27 | "Hooks report configuration error" (27) |
| `gh` or `jq` missing, or `gh` from `universe` (2.45 broken) | Exit 3 `gh not found`; or exit 6 with a deprecated-API error from `gh` | "gh from universe": install from the apt repository (11b); `apt-cache policy gh` |
| Token revoked or deleted on GitHub (HTTP 401) — or expired, with the 366-day fallback; token lacks access (403); SSO/approval pending | Exit 6, stderr with `gh`'s first line; nothing written | "GitHub token rejected": `--check`; look at the token page (present? expiry?); re-issue (11 "Re-issue") and overwrite the file; a 403 on a repository = selection or permission changed on GitHub |
| A non-expiring token is suspected leaked (file mode changed, VM compromise, value seen in a transcript) | Nothing observable from the script — the token keeps working until revoked | "Revoke the GitHub read token": delete it on GitHub first (instant 401 everywhere), then `shred -u` the file, then re-issue; check the security log for write events (none possible with read-only permissions) |
| Rate limit exhausted (403/429 `API rate limit exceeded`) | Exit 6, nothing written | "GitHub rate limit": wait for the reset (`--check` shows remaining/limit); a run needs ≤ ~300 requests |
| Network failure (DNS, TLS, proxy) | Exit 6 | "GitHub token rejected" (same entry, network branch): `curl -sI https://api.github.com` as `zyggy` |
| Unattended invocation (`ZYGGY_HOOKS=off`) | Exit 5, stderr `refused: unattended run`; nothing written | "Inventory refused: unattended run": expected; the skill is attended-only until 18–20 |
| More repositories than the cap | The most recent `cap` lines + marker line; one stderr line | "Inventory truncated": rerun with `--max` by hand (≤ 500) or raise the template default |
| A description or README line matches a secret pattern | Repository skipped, stderr names pattern and repository, counted | "Repository skipped (secret pattern)": expected; the owner fixes the description on GitHub if it really holds a secret |
| README missing (404) or unreadable (5xx, binary) | `(no description)`; 5xx adds one stderr line | "README not read": expected; nothing to fix |
| Zero repositories visible (or all excluded) | `inventory: no repositories visible to the token`; nothing written | "No repositories visible": the account owns no repository, the token's repository access was narrowed to an empty selection, the resource owner is wrong (an organisation's repositories need a token owned by that organisation), or every repository is on the exclusion list |
| Exclusion file present but malformed (a line that is not `owner/name`) or unreadable | Exit 3, stderr names the file and line; nothing written; `gh` never called | "GitHub inventory: configuration error" (exclusion branch): fix `instance/github-inventory-exclude.txt` on the workstation, commit, push, pull |
| A purpose line contains an instruction ("ignore previous instructions", "run …") | Written as data (bounded, fenced); Claude reports it, does not follow it (rule) | "Instruction found in repository text": expected; report to the owner; optionally add the repository to `instance/github-inventory-exclude.txt` |
| Same-day rerun | File replaced; no duplicates | none (expected) |
| A repository renamed/transferred between runs on different days | Two files with differing lines; 28 merges/supersedes | none (28's dedup) |
| Disk full / `mv` fails | Non-zero exit, `.tmp` removed by the trap, no torn file | "Disk full" (27) |
| The owner's session shows `gh: To get started with GitHub CLI, please run: gh auth login` from a **direct** `gh` call | Expected: Claude ran `gh` itself, which is forbidden; nothing leaked | "gh not logged in": expected and intended; the skill is the only path; `/doctor prompt-audit` if the rule was ignored |
| `github@claude-plugins-official` installed by mistake | Its MCP server fails auth (no `GITHUB_PERSONAL_ACCESS_TOKEN` exists); `/mcp` shows an error | "A `github` plugin was installed by mistake": disable at the scope it was installed, record in 0002, never define the variable |
| Token value pasted into the conversation by the owner | The 27 rule refuses to store it; `remember.sh` exit 2 (`github-token` pattern); the transcript may hold it (masked by the client) | "Remember refused" (27); the owner rotates the token if it was a real one |

## Deliberate deviations from the founding spec and the hand-off brief

- **Token in a 0600 file read by one script, `GH_TOKEN` per child** — instead of §8's "systemd `LoadCredential` for Central" and the brief's `gh auth login --with-token` (fed from a systemd credential or stdin). Rationale in the Decision Table (Q2): no unit exists for the interactive session that 31 may change, and the `gh` store authenticates every `gh` call of the user. The accepted §8 Secrets row ("Founding-spec amendments") says "0600 file … `LoadCredential=` from the same file when a unit needs it".
- **`gh` CLI, not the `github` plugin** — the brief allowed either; the plugin is a remote hosted MCP server with a session-wide bearer variable (verified from the marketplace cache). Recorded as the candidate route for the write-scope deliverable.
- **Dedicated `inbox/github-inventory-<date>.md` written by the script with the `lib.sh` primitives, replaced per day** — instead of the brief's `remember.sh` per line or an `areas/` seed. Same write primitives as `stop.sh`, same line grammar as `remember.sh`; rationale in Q3.
- **The script composes the purpose deterministically** — the brief's "description/README head → one-line purpose" is done without the model, for testability and injection bounding.
- **README read only when the description is empty** — the brief says "from the description and the README head"; reading the README for every repository would exercise Contents: read N times for no gain when a description exists.
- **Contents: read kept; the Metadata-only variant was offered at the gate and not chosen** — the owner confirmed "Contents + Metadata" (b1) on 2026-09-30.
- **"All repositories" instead of the brief's "selected vs all" question and the draft's "selected first" recommendation** — owner decision (a2) 2026-09-30; the bound moves from a list on GitHub to the resource owner + read-only permissions, and 31 ships the instance-owned exclusion list `instance/github-inventory-exclude.txt` (analyst's delegated decision) as the owner-side narrowing of what enters memory.
- **`affiliation=owner`** instead of the endpoint default `owner,collaborator,organization_member` — analyst's delegated decision (Decision Table): the resource-owner rule already bounds the token to the account's own repositories; `owner` makes the count comparable and removes a dependency on undocumented filtering.
- **Runbook entries instead of a `revoke-machine.md`-style file** for rotation/revocation (§11 lists `revoke-machine.md` for a machine's bus credentials, a different object).
- **`runbooks/central-claude-config.md` section 11**, not a new runbook file (the brief names that runbook).
- **No scheduled rotation; token issued without expiration (366-day fallback)** — the roadmap/brief asked for a "rotation period"; the owner ruled at the spec gate (2026-09-30) that a manual 90-day rotation is unacceptable ("a longer lifetime or automated refresh"). A non-expiring PAT has the same at-rest exposure as the automated alternative (a GitHub App private key, which "does not expire and instead needs to be manually revoked") with zero new code; the automated route (option c4 at the gate) is recorded for the write-scope deliverable (Findings 4). Owner decision (c3) 2026-09-30.
- **Private-repository clone deferred** — the roadmap's non-goal sentence tolerates "a clone only when the owner names one repository"; 31 keeps the token away from git entirely; a public clone is ordinary Bash use outside the skill.
- **`operations.md`/`AGENTS.md` gain a few lines** (exit codes, "What exists today" bullet) — the brief lists only `security.md`; `/doctor prompt-audit` and the 27 "do not claim what does not exist" rule require the other two to know the skill exists.
- **A `gh` stub and `tests/fixtures/github/gh-stub.sh` in the template** — the brief says "fixture API responses, no network"; the stub is how the script is driven without network while proving verbs, endpoints and the token's path (argv vs env).

## Edge Cases

| Case | Expected behavior |
|------|-------------------|
| `description` is whitespace only or `null` | Treated as empty → README fallback. |
| README is not Markdown (`README.rst`, `README.txt`, `README`) | `/readme` returns the preferred README whatever its name; the same line rules apply; a first line of `====`/`----` underlines is skipped. |
| README's first paragraph is longer than the budget | Cut at the fact limit with `…` (never a second line). |
| `language` is `null` (no code, docs-only) | `no language`. |
| `pushed_at` is `null` (empty repository) | `pushed never`; sorted last by the server. |
| A repository the token was granted but the owner has only `pull` on (collaborator) | `collaborator`; nothing else differs. |
| Two repositories with the same name under different owners | Distinct `full_name`s; distinct lines. |
| Non-ASCII in names/descriptions (accents, CJK, emoji) | Kept (UTF-8); `zy_char_count` counts characters; control characters removed. |
| The owner runs `/github-inventory` twice in one turn or in two sessions the same day | Last writer wins (whole-file replace, atomic); no torn file. |
| `--max` greater than the number visible | All lines, no marker. |
| `ZYGGY_NOW` set on the VM by mistake | Wrong date in the file name and lines — 27's rule: tests only; `instance/settings.local.json` never carries it. |
| The token was created with **All repositories** (the decided setting) | `N` = every repository the account owns (`affiliation=owner`); a collaboration owned by someone else is outside the resource owner and never appears; the cap applies to `N − X`; the marker line names how many were left out. |
| An exclusion line names a repository the token cannot see (typo, transferred, deleted) | Silently unused (it is a skip list, not an assertion); `--check`'s excluded count still counts the line; the owner sees the mismatch between `X` and the summary if they care. |
| The exclusion file is edited on the VM | Forbidden by the instance rule (tracked file → dirty tree → `git pull --ff-only` refuses); "VM checkout diverged" (27) applies. |
| The token's resource owner is an organisation (not chosen) | `user/repos` returns that organisation's accessible repositories only; `role` would read `collaborator` for all of them (owner is the org); documented in "No repositories visible" as the symptom of a wrong resource owner. |
| `gh` prints an update notice to stderr | Ignored: the script reads `gh`'s stdout only and reports stderr solely on non-zero exit; the stub emulates the notice in one test to prove it. |
| Claude decides to "help" by running `gh api` directly | Unauthenticated (`gh` has no token); the rule forbids it; nothing leaks. |
| The inventory file exists but the memory repository is dirty from other work | Not 31's concern; the file is untracked until the owner asks for a commit or 28 commits. |

## Out of Scope

- Any **write** scope on GitHub (issues, PRs, comments, pushes, stars, forks) and any write-capable tool or MCP server holding the token — a later deliverable after 18–20 (candidate: project `.mcp.json` to the remote GitHub MCP server with `X-MCP-Readonly`/`X-MCP-Tools`, token via `LoadCredential=`).
- Cloning repositories onto the VM (all of them, or a private one the owner names); giving the token to git in any form; `gh auth login`, `gh auth setup-git`, the `gh` credential store.
- Unattended or scheduled runs of the inventory; a timer; a dream step for it (28 consumes the file, nothing more); cross-day de-duplication (28).
- Reading issues, PR bodies, commit messages, code, releases, or more of the README than its first paragraph line; following links.
- `zyggy-org` repositories through the API (a personal-account token cannot; the instance and memory repositories are on the VM already); the memory repository through any API path; employer-owned repositories (§8 work boundary).
- `zyggy-bus`, the bus PAT and the §8 "GitHub PAT (read)" row (04/09); the registry and `agents.md` refresh (14); alerts on auth failure (22); any `Zyggy.*` code; any change to the 02 units or the Q4 wrapper.
- `allowed-tools` pre-approval; a second `gh`-based skill (e.g. reading one named repository's tree); the `github@claude-plugins-official` plugin; the laptops.
- Founding-spec edits (the owner applies the accepted O29 wording from "Founding-spec amendments").
- Narrowing the token back to "Only select repositories" (an owner action on GitHub if ever wanted; not part of the round trip).

## Findings forwarded to later deliverables (not blocking 31)

1. **28 —** the dream timer's environment must set `ZYGGY_HOOKS=off` (27 finding 2) — it is also what makes `github-inventory` refuse; 28's unit should add `InaccessiblePaths=%h/.config/zyggy` (or `ProtectHome=` equivalent) so no unattended run can read the token file at all.
2. **28 —** repeated inventories on different days produce lines that restate or supersede each other (`pushed` date moves, repositories appear/disappear/rename); the dream's "merge into an existing line if it restates or supersedes" (§7 step 3) is the dedup; a natural durable destination is `agents.md` or one `areas/<repo>.md` per active repository — 28's judgement.
3. **23/30 —** credential-file convention on Central: `~zyggy/.config/zyggy/<name>` (dir 0700, file 0600), read by one script or one MCP server, exported only to that child; `LoadCredential=<name>:<that file>` when a unit is involved; the AC-2 checks (`stat`, no settings/unit variable, no store) as the pattern.
4. **Write-scope deliverable (after 18–20) —** the remote GitHub MCP server supports `X-MCP-Readonly` and `X-MCP-Tools` headers and PAT bearer auth; a project-level `.mcp.json` (template with `${VAR}`, Finding 5 of spec 27) can set them where the plugin's cannot; the token would then need a session-wide variable → `LoadCredential=` + wrapper export → a 02-unit change with an owner decision. The credential itself should then become a **GitHub App** (option c4 of this spec's gate, verified facts in the table above): PEM at `~/.config/zyggy/github-app.pem` (0600, same discipline; does not expire, revoked in the app's settings), app id and installation id in `instance.md`, a `mint` step (JWT RS256 with `iat` −60 s / `exp` ≤ 10 min via `openssl dgst -sha256 -sign` + base64url, then `POST /app/installations/<id>/access_tokens` narrowed by `permissions` and, if wanted, `repositories`) producing a 1-hour `ghs_` token per run, `openssl` as a dependency, exit 6 on a failed mint, a stub endpoint `app/installations/<id>/access_tokens` and a throw-away fixture PEM in the template tests, runbook steps for app registration/installation/key download, the §8 Secrets row "GitHub App private key (Central)". Everything else in this spec (destination, line grammar, cap, exclusion list, injection controls, attended-only layers) carries over unchanged.
5. **14 —** the registry describes projects on the *laptops*; the GitHub inventory describes *repositories*; `agents.md` may end up citing both — 14 should reference the inventory lines' `owner/repo` as the join key.
6. **11 —** when `session-start.sh`/`remember.sh` become `zyggy` verbs, `inventory.sh`'s interface (env, token file, exit codes 0/3/4/5/6, line grammar, replace-per-day) is the contract for a `zyggy github inventory` verb; `secret-patterns.txt` stays the refusal source.
