## Assumptions (where the spec leaves a shape to the planner or an implementation choice is needed; each is reviewed at the named gate)

1. **A1 *(Gate A)* — `IDescribedSecretStore`**: the spec's internal `SecretStoreNames` gives the human names, but `secret list`'s `store` column and the credentials-directory note need the name **per entry** on Central (directory vs file). An internal interface with `StoreName` and `SourceOfAsync(tenant, name)` on every store is the smallest shape; `SecretStoreNames.Of(store)` falls back to the type name for a foreign implementation.
2. **A2 *(Gate A)* — `CredentialFileSecretStore.ListAsync` for another tenant** returns an empty list (names, not values, so no refusal is needed); for its own tenant it reports the fixed names whose files exist — no mode or content check in `ListAsync`.
3. **A3 *(Gate A)* — the CLI-wide net**: `CliApplication.RunAsync` catches `SecretStoreUnavailableException` around the invocation and prints `zyggy: secret store unavailable: <message>` with exit 6, so `status`, `verify`, `probe send`/`stats` and future verbs meet the spec's "exit 6 in the CLI with one stderr line" without each verb mapping it; `submit` and `probe listen` map it explicitly because they have a result/enum path. `InvalidDataException` (a corrupt value) is mapped to `StoreUnavailable` only in the start-up check (`CheckKeyAsync`); elsewhere it stays an infrastructure fault, as 03 decided.
4. **A4 *(Gate B)* — an empty credentials-directory file** is `SecretStoreUnavailableException("credentials-directory: <path> is empty")`, not `null`: an empty `LoadCredential=` source is a misconfiguration, not an absent secret (the `CredentialFileSecretStore` precedent refuses an empty file).
5. **A5 *(Gate C)* — zeroing on Windows**: the vault API takes a `string`, which cannot be zeroed; the store zeroes the intermediate `byte[]` it owns in `SetAsync` and nothing else — the spec's "where the code owns them".
6. **A6 *(Gate D)* — `TestHost.NodeConfigurationFor`** passes `SecretsSettings(SecretStoreKind.File)` so no in-process composition on Windows ever resolves Credential Manager, even though a later `.AddSingleton(store)` would win anyway.
7. **A7 *(Gate D)* — `AddSecretStore`'s environment**: an optional `IReadOnlyDictionary<string, string?>? environment` parameter (null → a one-time snapshot of the process environment inside the extension) so the Linux credentials-directory layer is unit-testable through the composition root; production passes nothing.
8. **A8 *(Gate D)* — "not available on this platform"**: `SecretStoreKind` is closed to `Os | File` and both exist on both OSes, so the spec's AC-3 branch for an explicit store that does not exist on this OS is unreachable; the reader's `secrets.store: one of os, file` is the only refusal and no dead code is written for the other.
9. **A9 *(Gate E)* — `--generate` with input**: with redirected stdin the verb reads it to end and refuses when non-empty (`--generate takes no input`); a terminal is never read for `--generate` (no prompt). A redirected but empty stdin (a service's null stdin) is accepted for `--generate`.
10. **A10 *(Gate E)* — the `list` layout**: a header line `name  bytes  fingerprint  store  role`, rows padded per column to the widest value, two spaces between columns, ordinal by name; `(none)` alone when empty. The spec names the columns, not the padding.
11. **A11 *(Gate E)* — the hidden reader**: `ConsoleHiddenInput` lives in `Zyggy.Cli` (the CLI owns the console; the Core verbs stay `Console.`-free); the command resolves a registered `IHiddenInput` from the container when a test registered one and falls back to `ConsoleHiddenInput`; Ctrl+C at the prompt is the host's cancellation (exit 5 through the verb's `null`/cancelled path), not a key the reader interprets.
12. **A12 *(Gate F)* — `public-api.md`** is a conventions file without a type table; AC-13's "listed in `public-api.md`'s table" is met by the XML documentation on every public type and the explicit list in this plan's "Shared rules"; the file is not edited.
13. **A13 *(Gate F)* — no gate-file edit**: 09 serves P1 but 13 closes it; `Gates/P1_WalkingSkeleton.cs` is proven unchanged (AC-12), not extended.
14. **A14 *(Gate F)* — the `CREDENTIALS_DIRECTORY` literal**: the spec's AC-13 sentence ("nothing outside `Zyggy.Core.Secrets` … except `ClaudeCodeCliRunner`") overlooks the existing m365, LinkedIn, memory deny-list and model-request readers; the hygiene fact enumerates today's holders exactly so a **new** holder fails, and 09 touches none of them.
