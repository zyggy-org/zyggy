## Overview

After this deliverable `zyggy memory archive add` recognises a Word, Excel or PowerPoint document by looking inside its ZIP container — `[Content_Types].xml` and the entry names, never the file name — and stores it as `archive/<project>/<slug>.docx|xlsx|pptx` with the 37 sidecar (`media_type` = the IANA wire string), the 37 commit (`archive add <project>/<slug>.docx`, body `media: <wire>; size: <n> bytes; sha256: <hex>`) and the 37 index line carrying a short label (`Word document`, `Excel workbook`, `PowerPoint deck` — owner decision OQ-4 (b)). A macro-enabled package (any extension), a package with VBA/ActiveX/macro-sheet parts, an OLE compound file (.doc/.xls/.ppt, or a password-protected OOXML file), an OpenDocument file, a template/slideshow variant, a ZIP that is not Office, and a malformed or hostile ZIP are refused with one new closed reason `office_refused (<detail>)` before anything is written; the sniffer extracts nothing to disk, decompresses at most two small entries with counted reads, prohibits DTDs and bounds entry count and declared sizes. Office item content is **not** scanned (owner decision OQ-1 (b)); `add` starts no process other than git. The dream and the offload need no code change beyond the type list: an Office item is an `ArchiveItem` path whose bytes the snapshot never loads, and `DriveWriteScope` passes the three extensions. A session reads an Office file — handed over or still in `archive/` — by copying it into the session download directory and running `zyggy m365 parse` on the copy (owner decision OQ-3 (b); template wording only, no new verb). Template, instance runbook and 0002 §39 record it; on Central one real docx, xlsx and pptx are archived, indexed and offloaded and one macro-enabled file is refused.

## Assumptions (where the spec is silent, leaves a shape to the planner, or is inconsistent with itself; each is reviewed at the named gate)

1. **A1 *(Gate after Step 7)* — release number**: the next **minor** after the live 0.6.0 (`v0.7.0`): public enum members are added (`ArchiveMediaType`, `ArchiveRefusal`) and the template's `zyggy-min-version` is bumped to it.
2. **A2 *(Gate A, Gate B)* — the `Longest` bound is one character short for a pptx line.** `Longest` composes `application/pdf` (15) + `.pdf` (3); a pptx line composes `PowerPoint deck` (15) + `.pptx` (4). AC-4 requires `Longest` unchanged ("the usage-time line check refuses exactly what it refused in 37"), and the Contracts' claim that labels ≤ 15 keep every line bounded does not hold for the extension. The plan keeps `Longest` byte-identical (AC-4) **and** adds a post-check on the actual composed line inside `ArchiveChecks` (after the two scans, before any write) that returns the pre-check's usage message with exit 4 (`ArchiveCheckResult.UsageError`, `ArchiveOutcome.Kind.Usage`). Without it, a 401-character pptx line would reach `RememberService` after the item and sidecar are on disk (37's "files on disk but not committed"). Alternative rejected: composing `Longest` with a 4-letter extension would change the boundary request `Longest` refuses, contradicting AC-4 literally. Reported to the owner as a spec inconsistency.
3. **A3 *(Gate B)* — where the OpenDocument check sits**: an ODF package has no `[Content_Types].xml`, so the `mimetype`-first-entry check runs after the open/bounds/name checks and **before** the `[Content_Types].xml` lookup; otherwise every ODF file would read `not_office`. A `mimetype` entry that is not first is ignored (`not_office`).
4. **A4 *(Gate B)* — `encrypted` detection reads one directory sector**: the CFB header's sector shift and first directory sector; the 128-byte entries of that sector only (no FAT chain walk); `EncryptedPackage` there → `encrypted`, otherwise `legacy_binary`. Office writes `EncryptedPackage` among the first directory entries; a crafted file that hides it deeper reads `legacy_binary` — still refused.
5. **A5 *(Gate B)* — committed samples under `tests/golden/office/`** (seven small hand-built files with `binary` git attributes, lengths and SHA-256 in `tests/golden/README.md`) plus the `OfficeBytes` builder in test code for every forged or large variant; the spec left the choice to the planner.
6. **A6 *(Gate B)* — `MediaSniffer.Sniff` changes signature** from `string? Internal type; `PostImage` uses `ImageType` only and is untouched; the existing `Sniff_*` facts read `.MediaType`.
7. **A7 *(Gate B)* — content types and part names compare `OrdinalIgnoreCase`**: OPC part names are case-insensitive and Office writers vary the case of content types; `macroEnabled` is case-insensitive by the spec; the duplicate-name rule already refuses two names equal ignoring case, so no two entries can collide.
