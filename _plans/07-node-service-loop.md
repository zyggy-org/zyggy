## Assumptions (where the spec leaves a shape to the planner or an implementation choice is needed; each is reviewed at the named gate)

1. **A1 *(Gate B, Gate C)* — the lease**: `Admitted` carries an `IDisposable Lease` taken inside `AdmitAsync` under the dispatcher's lock (the slot and the project are reserved atomically with the decision, so two listener passes cannot both admit the last slot); the listener disposes it when the tracked run ends or when the claim fails. The spec's separate `Track(job)` is subsumed; `JobsRunning` counts live leases.
2. **A2 *(Gate D)* — the health server**: a nested, empty web application (`CreateEmptyBuilder` + Kestrel core + routing core, `ListenLocalhost`) owned by `HealthServer` and started by `PollLoop` **after** the start-up check — the only way "never bound after a refusal" holds, since hosted services of the outer host start before `ExecuteAsync` has finished the check. It reads no configuration source, so `ASPNETCORE_URLS` cannot rebind it.
3. **A3 *(Gate D)* — where Node tests live**: `tests/Zyggy.Core.Tests` references only `Zyggy.Core` (rule 12); the `NodeHealth` serialisation facts (AC-11, "U" in the spec) and every host fact live in `tests/Zyggy.Integration/Node/` (the project already references `Zyggy.Node`). No new test project.
4. **A4 *(Gate D)* — AC-22's SIGINT**: .NET has no portable API to send SIGINT/SIGTERM to a child, and `Process.Kill` is SIGKILL; the "exits 0 on stop" fact is proven in-process (`NodeHost.RunAsync` with a cancelled token — the same path `ConsoleLifetime` takes on Ctrl+C/SIGTERM), and the out-of-process facts are those that terminate by themselves (`--version`, exit 3). `AddWindowsService()`/`AddSystemd()` are proven inert because the in-process host runs under the test runner, which is neither.
5. **A5 *(Gate D)* — "two `fake-claude` processes exist at once"**: `ProcessProbe` is destructive on Windows (it deletes the directory), so concurrency is asserted through `/health` `jobsRunning: 2` plus both capture files existing before any report lands; `ProcessProbe` is used only **after** the runs for the "no orphan" facts.
6. **A6 *(Gate B)* — `AddJobDispatcher()`**: lives in `Zyggy.Core.Jobs.ServiceCollectionExtensions` (registers `JobDispatcher`, `JobGate`, `PollModeSelector` from the registered `NodeConfiguration`'s `workHours`); only `NodeHost` and the Node tests call it; `AddNodeServices` does not, so the CLI's probe verbs keep admit-all and `Active`.
7. **A7 *(Gate A)* — hosting API names**: with `HostApplicationBuilder` the §9 `UseWindowsService()`/`UseSystemd()` are `builder.Services.AddWindowsService()`/`AddSystemd()` (same packages, same runtime detection).
8. **A8 *(Gate A)* — `NodeHost.RunAsync(args, ct, configure = null)`**: the optional `configure` lets the exit-code facts (AC-15, port in use) run the whole `RunAsync` path with the harness's hooks; production passes none.
9. **A9 *(Gate D)* — the `Debug` line**: `NodeHost` logs `node.json read from {Path}` at `Debug` so AC-21's "`log.level: Debug` yields Debug lines" has a deterministic source; a `304` tick stays silent at every level the loop controls.
10. **A10 *(Gate D)* — timestamps**: a `JsonConverter<DateTimeOffset?>` writes `yyyy-MM-ddTHH:mm:ssZ` (UTC, seconds) because the default writes an offset form.
11. **A11 *(Gate D)* — `BareRepoHeadHandler.Freeze`**: an additive test-harness flag that makes the doorbell lie for AC-19.
12. **A12 *(Gate A)* — `NodeStartupException(ExitCode, Message)`**: `Build` cannot return an exit code; `RunAsync` maps the exception to the stderr line and the code (3 or 6).
