Interface, emulating exactly the `gh api` calls of the spec's Contracts table:
- Parses `api` then options in any order: `--method GET|<other>`, `-X <verb>`, `--paginate`, `-f k=v` / `--raw-field k=v` (repeatable), `-H <header>` (repeatable), `--jq <filter>`, `-i`/`--include`, and one positional endpoint. Appends one line `argv=<all arguments joined by U+001F> GH_TOKEN=<value or "unset">` to `$GH_STUB_LOG` **before** deciding anything, so refused calls are logged too.
- Refuses with exit `99` and stderr `stub: write verb` when the method is not `GET` (an explicit `-X`/`--method` other than GET, or fields without `--method GET` — the real `gh` would POST), and with exit `99` and stderr `stub: unknown endpoint <e>` when the endpoint is not `user`, `user/repos`, `repos/<o>/<r>/readme` or `rate_limit`.
- `GH_STUB_FAIL=<endpoint>:<status>[:<message>]` — when `<endpoint>` equals the requested endpoint (glob `repos/*/*/readme` allowed): exit 1, stderr `gh: <message or "HTTP error"> (HTTP <status>)`; for `user/repos` the stub **first prints page 1 to stdout, then fails** (mid-pagination, assumption 2). `GH_STUB_NOTICE=1` — every successful call also prints `A new release of gh is available: 2.x.y → 2.x.z` on stderr (Edge case "update notice").
- `user` → `cat user.json` (`{"login":"alice", …}`); with `-i` → the lines of `user-headers.txt` (default fixture has `HTTP/2.0 200 OK`, `X-Ratelimit-…`, **no** `GitHub-Authentication-Token-Expiration`), an empty line, then the body; `GH_STUB_HEADERS=user-headers-expiring.txt` selects the variant that carries `GitHub-Authentication-Token-Expiration: 2027-10-01 10:00:00 UTC` (assumption 1).
- `user/repos` → the concatenation of `jq -c '.[]'` over `repos-page-1.json`, `repos-page-2.json` (in name order), or over the single file named by `GH_STUB_REPOS` (`repos-empty.json`, `repos-secret.json`, `repos-sanitising.json`, `repos-second-run.json`); it asserts the fields `--method GET`, `per_page=100`, `sort=pushed`, `affiliation=owner` are present (else exit 98, stderr `stub: missing field …`) so AC-21 is a hard failure, not a log inspection only.
- `repos/<o>/<r>/readme` → `cat readme-<o>-<r>.md` when the file exists and the `Accept: application/vnd.github.raw+json` header was given (else exit 98 `stub: readme without raw media type`); absent → exit 1, stderr `gh: Not Found (HTTP 404)`.
- `rate_limit` → `cat rate_limit.json` (`{"resources":{"core":{"limit":5000,"remaining":4993,…}},"rate":{"limit":5000,"remaining":4993,…}}`).
