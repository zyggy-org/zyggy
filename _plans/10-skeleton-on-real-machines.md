## Shared rules for this plan

- **Names in every file**: tenant `acme`, machines `central` and `home-laptop`, keys `acme/1` (the spike key) and `acme/2` (the first rotation), home `<zyggy-home>`, admin `<vm-admin>`, project `<project>`, version `<x>`. Nothing in `deploy/`, the runbooks, the READMEs, the tests or this plan names the owner, the employer, a real host, user name other than `zyggy`, token id, key fingerprint, mailbox, GUID, `/home/<name>`, `/srv/…` or `C:\Users\<name>` (`memory/long-term/repo-public-hygiene.md`; `zyggy-core`'s `hygiene_paths` flags `/srv/` and `C:\Users\`). `%LOCALAPPDATA%`, `$env:LOCALAPPDATA`, `~/.config/zyggy`, `~/.local/share/zyggy` are the only home forms.
- **Rule R1**: the only shell of this deliverable is `deploy/windows/install.ps1` (the reason, stated in the script's header comment and in `deploy/README.md`: it runs before any Zyggy binary is in place, copies files, edits the user's PATH and registers a Task Scheduler task — things no test can exercise and the owner wants to read line by line) and the one-line `systemctl`/`cp`/`ln`/`install` commands in the runbooks. The task's command line carries only the exit-code hand-through (`exit $LASTEXITCODE`). No new tool chain in CI: the `pwsh` already used by `ci.yml` parses the script (Step 3).
- **PowerShell 5.1 and no parser in .NET**: `System.Management.Automation` is not available without a package, so no test parses the script (A2). What **is** checked: the static invariants of AC-2 by text (Step 2), a forbidden-token list for PowerShell 7-only syntax (`??`, `?.`, `&&`/`||` pipeline chains, `-Parallel`), and a `pwsh` AST parse in CI on both runners (Step 3) — PowerShell 7's parser accepts every 5.1 construct, so a parse error there is a real error; 5.1 compatibility itself is proven by AC-10 on the laptop.
- **Exact texts are the contract**: the unit and the drop-in are the spec's Contracts texts byte for byte (LF, no trailing whitespace, one trailing newline); the task table and the `install.ps1` sequence are asserted token by token; the `node.json` template between `# node.json-template-begin` and `# node.json-template-end` is the spec's JSON with the five placeholders `<tenant>`, `<machine>`, `<signWith>`, `<busLocalPath>`, `<userprofile>`.
- **Never a value**: `SecretSweep.AssertAbsent` over every deploy file and every README text in every step; the drop-in names two secret **paths** and no value; the installer never reads, prints or stores a password or a secret (AC-2 tokens).
- **Shared-contract edits**: none on the wire. Before touching `SourceHygieneTests.cs` or `ci.yml`, run the whole suite and note the counts; after GREEN the counts may only grow; `git diff tests/golden/` is empty; `Gates/P1_WalkingSkeleton.cs`, the Node integration tests and the 09 OS-store tests are **unedited** (AC-19); `Directory.Packages.props` unedited (24 rows).
- **Owner-facing wording** (`memory/owner-facing-wording.md`): "signing key" and "fingerprint", never "hash"; PowerShell 5.1 snippets with `$env:LOCALAPPDATA`; every runbook command prefixed with its role — `[central/zyggy]`, `[central/<vm-admin>]`, `[home-laptop/user PowerShell]` (there is no elevated shell on a laptop).
- **Two repositories, two branches, nothing committed**: `zyggy` on `feature/10-skeleton-on-real-machines`, `zyggy-core` on `feature/10-runbooks`; the executor reports per repository at the gate (auto-memory "Owner reviews before commit").
